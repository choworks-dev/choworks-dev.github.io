# choworks.dev 블로그

AI 트랜스폼 여정을 기록하는 블로그입니다. 마크다운 원본과 빌드 스크립트만 버전 관리하고,
GitHub Actions가 push마다 빌드해서 배포합니다. 빌드 결과물(`site/`)은 파생물이라 커밋하지 않습니다.

정적 사이트 생성기를 직접 만들어 씁니다. 런타임 의존성은 `front-matter` 와 `marked` 둘뿐이고
마크다운을 HTML로 바꾸는 변환기는 `scripts/build.js` 파일 하나입니다.

## 구조
```
choworks-dev.github.io/
├── content/                 # 글·소개 원본(마크다운). ko = content/posts-kr/, en = content/posts-en/
│   └── site.json            # 사이트 설정(브랜드·태그라인·이메일·customDomain 등)
├── assets/                  # 정적 원본(스타일 등). 빌드가 site/assets/ 로 그대로 복사
│   └── style.css            # 사이트 디자인 원본. 여기를 고치면 배포에 반영됨
│   └── diagrams/            # 그림 SVG. hero-* 는 npm run hero 가 만든 것이라 손으로 안 고침
├── scripts/build.js         # 마크다운 → 정적 HTML 변환기
├── scripts/diagram.js       # 본문의 {{svg: 이름}} 을 SVG 로 펴 넣음
├── scripts/make-hero.js     # 표지 그림 찍어내기 (hero-kit.js 틀 + hero-specs.js 내용)
├── package.json / package-lock.json
├── .github/workflows/deploy.yml   # push 시 자동 빌드+배포
├── .gitignore               # site/, node_modules/ 등 제외
└── site/                    # (git 무시) 빌드 결과물
```

## 진실의 원본은 마크다운 하나
- 에이전트가 글을 "생성"하든, 사람이 "수정"하든 → 모두 `content/`의 **같은 .md 파일**을 편집하는 것.
- 디자인을 고칠 땐 `assets/style.css`를 수정 (`site/assets/style.css`는 복사본이라 덮어써짐).
- **빌드된 `site/`의 HTML은 절대 직접 고치지 말 것** (빌드 때마다 덮어써짐).
- 특수 꾸밈이 필요하면 .md 안에 HTML을 직접 섞어도 됨.

## 로컬에서 돌려보기
```
npm install     # 최초 1회
npm run dev     # http://localhost:4000, 저장하면 자동 재빌드 + 브라우저 자동 새로고침
npm run build   # 1회 빌드만 (site/ 생성)
```
- `content/`, `assets/`, `scripts/build.js` 를 저장하면 즉시 다시 빌드되고 열려 있는 탭이 스스로 새로고침됩니다.
- 응답에 `no-store` 를 붙이므로 **로컬에서는 Ctrl+F5가 필요 없습니다.**
- `site/index.html` 을 파일로 직접 열지 말 것. HTML이 `/assets/style.css` 처럼 루트 절대경로를 쓰기 때문에
  `file://` 로 열면 CSS가 안 잡힙니다. 반드시 위 서버로 확인하세요.
- 포트를 바꾸려면 `PORT=5000 npm run dev` (PowerShell: `$env:PORT=5000; npm run dev`).

## frontmatter
```
---
title: 글 제목
date: 2026-08-01
description: 목록·검색에 보일 한 줄 요약.
tags: [태그1, 태그2]
draft: true   # 준비되면 지우거나 false
---
본문...
```
새 글은 `content/_post-template.md` 를 `content/posts-kr/YYYY-MM-DD-슬러그.md` 로 복사해서 시작합니다.
영어판은 `content/posts-en/` 에 같은 파일명으로 둡니다.

### 초안(draft)
frontmatter에 `draft: true`를 넣으면 **커밋은 되지만 사이트에는 공개되지 않습니다.**
다 다듬은 뒤 `draft: false`(또는 줄 삭제)로 바꿔 push하면 공개됩니다.
아직 다듬는 중이라 `description` 을 채우지 못했다면 `draft: true` 를 넣으세요. 검사 대상에서 제외됩니다.

## 검색 최적화(SEO)는 빌드가 자동 처리
frontmatter만 제대로 채우면 아래가 **모든 글에 자동으로** 들어갑니다. HTML을 직접 손댈 일은 없습니다.

- `<title>` / `meta description` / `canonical`
- Open Graph (`og:type=article`, `og:title/description/url`, `article:published_time`, `og:locale`)
- 구조화 데이터 JSON-LD (`BlogPosting`, 제목·요약·발행일·저자·발행처·태그)
- `hreflang` 한/영 상호 연결, `<time datetime>`, `sitemap.xml` 의 `lastmod`
- **저자 표기**. 제목 위 `날짜 · 글쓴이` 한 줄, 글 하단 저자 카드(이름·소개·소개 페이지/Email/GitHub 링크)

> 모든 글은 `buildPost()` 하나를 거쳐 생성됩니다. 위 항목은 여기에 들어 있어서
> **새 글을 추가하면 예외 없이 함께 붙습니다.** 글마다 따로 챙길 것이 없습니다.
> 저자 이름·소개 문구는 `content/site.json` 의 `authorKo` / `authorEn` / `authorBioKo` / `authorBioEn`
> 한 곳에서 관리하며, 여기를 고치면 과거 글까지 전부 다시 반영됩니다.

**빌드가 직접 검사합니다.** 아래가 비어 있으면 빌드가 실패해 배포되지 않습니다.

| 항목 | 없으면 |
|---|---|
| `title`, `date`(YYYY-MM-DD), `description` | **오류 → 빌드 중단** |
| 슬러그 중복 | **오류 → 빌드 중단** (뒤 글이 앞 글을 덮어쓰는 사고 방지) |
| `description` 길이, `title` 길이, `tags` 없음 | 경고 (배포는 됨) |
| 제목·description·본문에 긴 하이픈(`—` `–`) | 경고 (배포는 됨) |

**길이 기준이 언어마다 다릅니다.** 검색 결과에서 잘리는 기준은 글자 수가 아니라 픽셀 폭인데,
한글은 한 글자가 영문 두 글자쯤의 폭을 차지합니다. 같은 자릿수라도 한국어가 먼저 잘립니다.

| | `title` | `description` |
|---|---|---|
| 한국어 | 30자 이내 | 40~80자 |
| 영문 | 60자 이내 | 110~155자 |

2026-08-22 이전에는 영문 기준(40~160)을 한국어에도 그대로 적용하고 있었습니다.
그래서 한국어판 여덟 편 중 일곱 편의 설명이 검색 결과에서 잘리고 있었는데 경고가 안 떴습니다.

**글 페이지의 `<title>` 에는 브랜드를 붙이지 않습니다.** `" · choworks.dev"` 가 15자라
한국어 제목 자리의 절반을 먹습니다. 브랜드는 검색 결과에 도메인으로 따로 표시되므로
제목에서 한 번 더 말할 이유가 없습니다. 홈·소개·404 에는 그대로 붙습니다.
공유 카드(`og:title`)에는 붙습니다. 링크를 받은 사람에게는 어느 사이트인지가 보여야 합니다.
| 짝 언어판 없음 (한쪽 언어로만 있는 글) | 경고 (배포는 됨) |

### 글은 한국어판과 영문판을 한 쌍으로 낸다
글 하나를 만든다는 것은 `content/posts-kr/` 와 `content/posts-en/` 에 **같은 슬러그로 두 편**을
만든다는 뜻입니다. 한쪽만 있으면 그 글은 hreflang 없이 나가고 빌드가 경고합니다.
영문판은 직역이 아니라 영어권 독자에게 맞춘 판으로 씁니다.

빌드가 막지는 않습니다. 짝을 일부러 미루는 경우도 있기 때문입니다.

### 문체 규칙: 긴 하이픈을 쓰지 않는다
독자가 "AI가 쓴 글"이라고 가장 먼저 알아채는 지점이라, 노출되는 모든 텍스트에서 em dash(`—`)와
en dash(`–`)를 쓰지 않고 쉼표나 마침표로 문장을 다시 구성합니다.
의도적으로 넣을 때만 직접 넣으며, 그 경우 빌드 경고는 무시해도 됩니다(배포는 정상 진행).

## 글마다 표지 그림을 넣습니다

모든 글은 머리말 바로 밑에 표지 그림(히어로)이 한 장 들어갑니다. **글을 냈는데 표지가 없으면
그 글은 아직 미완성입니다.** 제목만 있는 글은 목록에서 다른 글과 구별되지 않고, 링크를 공유해도
아무것도 안 보입니다.

본문에는 한 줄만 적습니다. `scripts/diagram.js` 가 SVG를 그 자리에 통째로 펴 넣습니다.

```
---
title: ...
---

{{svg: hero-<슬러그>}}          ← 영문판은 {{svg: hero-<슬러그>-en}}

첫 문단부터 본문...
```

### 만드는 법

그림 파일은 손으로 그리지 않고 찍어냅니다.

```
npm run hero                   전부 다시 만듭니다
npm run hero -- <슬러그>        그 글 것만
```

새 글을 냈으면 `scripts/hero-specs.js` 의 `SPECS` 에 항목 하나를 더하고 위를 돌립니다.
항목에서 정하는 것은 넷뿐입니다.

| 항목 | 무엇 |
|---|---|
| `motif` | 가운데 그림. **글마다 다른 유일한 부분** |
| `chip` | 오른쪽 위 작은 표시. 영문 짧은 말. 한국어판도 영문을 씁니다 |
| `caption` | 아래 한 줄. 두 토막으로 적습니다. 가로는 `·` 로 잇고 세로는 두 줄로 나눕니다 |
| `title` / `desc` | 화면 낭독기용. 그림을 못 보는 사람이 읽는 문장입니다 |

한 편에 네 벌이 나옵니다. 한국어 가로 · 한국어 세로 · 영문 가로 · 영문 세로.
세로가 따로 있는 이유는, 900px 그림을 폰에서 그대로 줄이면 아래 한 줄이 5px 로 찍혀
글자가 안 읽히기 때문입니다. 읽을 수 없으면 그림이 아닙니다.

파일은 셋으로 갈려 있습니다.

| 파일 | 맡는 것 |
|---|---|
| `scripts/hero-kit.js` | 테두리·그러데이션·점 무늬·칩·캡션. **글마다 같은 것** |
| `scripts/hero-specs.js` | 가운데 그림과 문구. **글마다 다른 것** |
| `scripts/make-hero.js` | 위 둘을 합쳐 파일로 떨굽니다 |

`assets/diagrams/hero-*.svg` 는 **손으로 고치지 마세요.** 다음 실행 때 덮어씁니다.
고칠 곳은 언제나 `hero-specs.js` 입니다.

### 표지에 지켜야 하는 것

**숫자와 고유명사를 넣지 않습니다.** 금액도 회사 이름도 제품 이름도 표지에는 없습니다.
표지가 요약이 되면 본문을 읽을 이유가 줄어듭니다. 표지는 궁금하게만 만들면 됩니다.
그래서 그림 안의 글자도 진짜 글이 아니라 **글자 자리를 나타내는 막대**입니다. 이렇게 해야
한국어판과 영문판이 같은 그림을 쓸 수 있고, 고칠 곳도 늘지 않습니다.

**본문을 설명하지 않습니다.** 설명하는 그림은 본문 중간에 따로 넣습니다.
표지는 인상을 만들고 본문 그림은 이해를 돕습니다. 하는 일이 다릅니다.
한 글에 둘 다 있어도 됩니다. `record-everything` 이 그런 경우입니다.

**글마다 다른 모양이어야 합니다.** 표지가 다 비슷하면 안 그린 것과 같습니다.
지금 여덟 편은 출발선 · 끊긴 막대 · 줄어든 단계 · 코드와 노드 · 밀려난 원 · 어긋난 눈금 ·
오가는 말풍선 · 쌓인 더미로 전부 다릅니다. 새 글은 이 중 아무것과도 안 겹치는 모양을 찾습니다.
못 찾겠으면 그건 표지 문제가 아니라 그 글이 무엇에 관한 글인지 아직 안 정해진 것입니다.

**색을 직접 적지 않습니다.** `--card` `--border` `--muted` `--accent` 만 씁니다.
이 사이트는 다크와 라이트 두 모드이고, 색을 박아 넣으면 한쪽에서 안 보입니다.
`hero-kit.js` 의 `card()` `bar()` `dot()` `ring()` `line()` 을 쓰면 저절로 지켜집니다.

### 왜 `<img>` 로 걸지 않는가

`<img>` 로 걸면 그림이 페이지의 CSS 를 못 봅니다. 그러면 테마 토글을 눌러도 그림만 안 바뀌어서,
다크 화면 한가운데 하얀 사각형이 남습니다. 그래서 SVG 를 통째로 펴 넣습니다.

펴 넣을 때 `scripts/diagram.js` 가 두 가지를 합니다.
`data-standalone` 이 붙은 것(파일을 그냥 열어봤을 때만 쓰는 배경색)을 걷어내고,
빈 줄과 들여쓰기를 없애 한 덩어리로 만듭니다.
**뒤엣것이 중요합니다.** `marked` 는 빈 줄에서 HTML 덩어리를 끊고 그다음부터 다시 마크다운으로
읽기 때문에, 들여쓴 SVG 줄이 전부 코드 블록이 되어 그림 절반이 태그 글자로 나갑니다.
2026-08-18 에 실제로 그렇게 나갔고 브라우저는 오류 없이 조용히 그렇게 그립니다.

### 대표 이미지(선택)
`assets/og.png` (1200×630 권장) 를 넣고 `content/site.json` 의 `ogImage` 를 `"/assets/og.png"` 로 채우면
링크 공유 시 썸네일이 붙습니다. 비워두면 이미지 없는 카드로 안전하게 처리됩니다.
